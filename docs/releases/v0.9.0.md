# v0.9.0 Release Readiness Notes

## Summary

v0.9.0 is the **OBS Browser Source Workflow Polish** release.

It improves discovery, copying, opening, and automated contract protection for OBS-friendly routes while preserving the plain handwritten R3F renderer, Native Core ownership boundaries, and MotionFrame ownership boundaries. It is not a new tracking backend and is not real OBS certification.

The implementation landed through these merged PRs:

- #502, merge commit `ca2ac4a3b2dd471ca2f3301ee338dd69d9a6fcc8` — expose a typed Electron OBS dummy preview URL.
- #503, merge commit `d3126676087c1d0af6bcf4b88e64a19f6a231341` — add the dedicated Electron Desktop OBS Browser Source setup workflow.
- #504, merge commit `e32011d5544ef5a573c383eff426892b96ed5ca1` — add focused Web Preview OBS route-contract checker coverage.

## Completed slices

### #498 / PR #502

Electron now exposes a dedicated OBS dummy preview URL through its typed runtime-status contract:

```txt
http://localhost:5173/?mode=obs&source=dummy
```

The URL is exposed alongside the native OBS URL. Safe local URL handling remains protected by the existing local allowlist, and opening previews uses the existing safe Electron preview-opening path. Dummy OBS does not require Native Core, the webcam, or the MotionFrame bridge.

No new IPC channel, dependency, network behavior, or non-local route was added. The route remains localhost-based. Opening the URL is not evidence of real OBS Browser Source validation.

### #499 / PR #503

Electron Desktop now has a dedicated **OBS Browser Source** setup workflow with separate OBS dummy and OBS native panels. Each panel provides Copy and Open actions for its URL, recommends `1920 × 1080` as a starting size, explains localhost-only usage, states that camera frames remain local, and distinguishes dummy versus native runtime requirements.

The workflow includes source-, action-, URL-, and runtime-aware pending/success/failure feedback with accessible status and alert semantics. Ordinary Dummy and Native preview controls remain in the general Preview URLs section.

Open uses the existing protected Electron external URL path. Copy uses the browser clipboard capability. Open does not automatically start the native pipeline. No new IPC, dependency, or network behavior was added.

This slice did not validate the Electron GUI, OBS, webcam, native-runtime visuals, or target hardware.

### #500 / PR #504

Web Preview now has a focused OBS route-contract checker. It protects:

- independent mode/source/debug query parsing
- `mode=obs`
- dummy/native source independence
- transparent document, body, and root backgrounds
- transparent OBS shell and canvas
- full viewport `100vw × 100svh`
- exclusion of standard source-status controls from normal OBS output
- exclusion of renderer calibration controls from normal OBS output
- persisted renderer calibration still flowing into `AvatarScene`
- `debug=motion` remaining an explicit opt-in
- component-bounded assertions for `MotionDebugOverlay` and `AvatarScene`
- focused root and Web Preview test-chain integration

This is automated source/behavior evidence, not real OBS Browser Source visual validation.

## Architecture and privacy boundaries

v0.9.0 does not add or change native OBS plugin support, MediaPipe integration or enablement, production tracking backend selection, model/task assets, runtime downloads, Native Core tracking algorithms, camera access behavior, MotionFrame schema, Motion Protocol schema, localhost MotionFrame transport, Electron-to-Web Preview calibration synchronization, cloud upload, telemetry, analytics, remote inference, remote synchronization, external frame processing, hidden or new network behavior, camera-frame persistence, MotionFrame-history persistence, or raw-tracking-history persistence.

Native Core owns camera access and tracking. Electron owns the Desktop shell, setup UI, preview launching, and native process lifecycle. Web Preview owns OBS-friendly renderer behavior. MotionFrame remains the stable Native Core-to-renderer contract.

Camera frames remain local. OBS URLs remain localhost-based. Renderer calibration remains browser-local and renderer-owned. Normal OBS output excludes standard calibration controls, while persisted renderer calibration can still affect OBS avatar rendering. `debug=motion` remains an explicit optional diagnostic path.

## Known limitations and remaining local/manual checks

Known limitations, none of which are regressions:

- No native OBS plugin was added.
- No automatic OBS scene or Browser Source configuration was added.
- Headless checks do not prove real OBS alpha compositing.
- No new tracking backend was added.
- No real eye, mouth, expression, landmark, or blendshape tracking was added.
- No VRM, GLB, Live2D, or custom avatar loader was added.
- No Electron-to-Web Preview calibration synchronization was added.
- `1920 × 1080` is a recommended starting point, not a universal requirement.
- Native OBS still requires the local native pipeline and MotionFrame bridge.
- Dummy OBS uses built-in local demo MotionFrames and does not validate native runtime.
- Electron GUI validation remains incomplete unless separately evidenced.
- Real OBS Browser Source validation remains incomplete unless separately evidenced.
- Webcam, native runtime, packaged Electron, and target hardware validation remain unclaimed unless separately performed.
