# v0.10.0 Release Readiness Notes

## Summary

v0.10.0 is the **Local Avatar Preview Foundation** release and the first LVK foundation for previewing a user-selected local GLB avatar in the standard Web Preview.

One local `.glb` file can be selected from the browser UI. The selected file bytes are read with `File.arrayBuffer()`, parsed through the existing Three.js `GLTFLoader` path, and kept as renderer-owned, in-memory avatar state. External avatar resources are blocked by the local-only loading boundary; generated `blob:` and `data:` resources remain local handling and do not introduce remote networking.

The implementation provides explicit `idle`, `loading`, `ready`, `error`, and reset behavior. Unsupported selections do not replace the current working avatar. Failed replacement loads preserve the current working GLB when one exists, while failure without a current GLB preserves the built-in primitive fallback. Reset restores the built-in primitive avatar.

A ready GLB is rendered through the existing renderer-owned `AvatarMotionState` path. Only renderer root translation and coarse overall orientation are applied through wrapper groups; authored GLB model transforms are preserved. The built-in primitive remains the default and fail-safe fallback. Dummy and native MotionFrame source selection remains supported. Renderer calibration, smoothing, idle approximation, and lost-tracking fallback remain upstream of avatar renderer selection. Standard OBS output remains transparent and full viewport, and avatar-selection controls remain excluded from standard OBS output.

Focused local-avatar source/behavior contract coverage was added. v0.10.0 does not claim standardized humanoid animation, bone retargeting, facial rig control, expression support, complete arbitrary-GLB compatibility, or production avatar-format support.

## Completed slices

### #507 / PR #511

This slice added `useLocalGlbAvatar`, a typed renderer-owned local avatar controller, local `.glb` extension validation, loading through a browser `File`, `File.arrayBuffer()`, `GLTFLoader.parseAsync`, a local-only `THREE.LoadingManager`, URL modification that permits generated `blob:` and `data:` resources, and rejection of disallowed external resource resolution.

It added explicit `idle`, `loading`, `ready`, and `error` states, reset behavior, stale-load generation protection, and disposal for geometry, material, and texture resources owned by retired local GLB assets. The implementation parses the `ArrayBuffer` directly and does not create an object URL, so there is no object URL revocation behavior to claim.

It also added standard Web Preview local GLB selection UI and kept avatar-selection controls excluded from standard OBS output. This slice did not render the loaded GLB into the scene yet; `DummyAvatar` remained the rendered avatar until the #508 integration slice.

### #508 / PR #512

This slice added `LoadedGlbAvatar`, stable wrapper groups around the imported scene, root translation from `motion.rootPosition`, coarse orientation from `motion.headRotation`, the same `fallbackState.renderedMotion` for primitive and GLB renderers, and conditional `DummyAvatar` / `LoadedGlbAvatar` renderer selection.

It added safe post-React-commit disposal of retired rendered assets, retention of the current working GLB during replacement loading, retention of the current working GLB after replacement failure, reset cleanup, unmount cleanup, compatibility with dummy MotionFrame source selection, compatibility with native MotionFrame source selection, compatibility with renderer calibration, compatibility with renderer smoothing, and continued OBS transparency and control exclusion.

Generic GLB assets do not receive bone-name inference, humanoid retargeting, head-bone mapping, eye mapping, gaze mapping, mouth mapping, expression mapping, landmark mapping, blendshape mapping, morph-target mapping, animation retargeting, automatic model centering, automatic scaling, or automatic orientation normalization. Only renderer-level root translation and coarse overall orientation are applied through wrapper groups.

## Architecture and privacy boundaries

v0.10.0 does not add or change a VRM runtime, VRM humanoid semantics, Live2D, multi-format avatar loading, multi-file `.gltf` dependency resolution, remote avatar URL input, external avatar fetching, runtime downloads, automatic bone-name inference, automatic humanoid retargeting, eye tracking for arbitrary GLB assets, gaze tracking for arbitrary GLB assets, mouth tracking for arbitrary GLB assets, expression mapping for arbitrary GLB assets, landmark mapping for arbitrary GLB assets, blendshape mapping for arbitrary GLB assets, morph-target mapping for arbitrary GLB assets, animation retargeting, Native Core tracking algorithms, camera access behavior, MotionFrame schema, Motion Protocol schema, localhost MotionFrame transport, Electron behavior, Electron native process lifecycle, Electron-to-Web Preview avatar synchronization, Electron-to-Web Preview calibration synchronization, cloud upload, telemetry, analytics, remote inference, remote synchronization, external frame processing, hidden network behavior, new network behavior, avatar-byte persistence, camera-frame persistence, MotionFrame-history persistence, or raw-tracking-history persistence.

Native Core still owns camera access and tracking. Electron still owns the desktop shell and native process lifecycle. Web Preview owns local avatar selection and rendering. Shared protocol code still owns the stable MotionFrame contract. MotionFrame remains the stable Native Core-to-renderer contract. Selected avatar files remain local, selected avatar state remains in memory, and camera frames remain local.

## Known limitations and remaining local/manual checks

Known limitations:

- Arbitrary GLB scale, origin, orientation, and framing are not normalized.
- There is no automatic centering, automatic scaling, or automatic retargeting.
- There are no humanoid bone semantics or standardized head-bone semantics.
- There is no eye, gaze, mouth, expression, morph-target, animation playback, or animation retargeting foundation claimed for arbitrary GLB files.
- Detailed eye/gaze/mouth visualization remains specific to the primitive renderer.
- Selected avatar state is in memory and does not survive page reload.
- Separately opened pages or windows do not automatically share the selected in-memory avatar.
- OBS pages do not automatically inherit avatar selection from another page.
- There is no Electron avatar-selection synchronization.
- No bundled production avatar asset is provided.
- No real browser, GLB, OBS, GPU, webcam, Native Core runtime, packaged Electron, or target hardware validation is claimed.
- This is a foundation, not final avatar-format support.

A technically valid GLB can still appear too large, too small, off-center, incorrectly oriented, or outside the expected camera framing because normalization is intentionally outside v0.10.0 scope.
