# v0.4.0 Release Readiness Notes

## Summary

v0.4.0 is a **local runtime confidence and native pipeline readiness** closeout for LVK after the v0.3.0 local tracking quality release-readiness pass.

This release readiness note summarizes the completed native dummy pipeline, Electron runtime status, no-frame startup warning, Web Preview native-source guidance, and renderer-side calibration preset polish without expanding runtime scope. LVK remains local-first: camera frames stay local, `MotionFrame` remains the renderer contract, and localhost MotionFrame transport remains the native preview boundary.

## Completed slices

- Added a bounded native dummy pipeline WebSocket smoke path that pipes native dummy/noop MotionFrame stdout into the local bridge, connects to `ws://127.0.0.1:45731/motion`, validates native MotionFrame messages, and cleans up the child processes.
- Surfaced Electron native runtime readiness status so the desktop UI can summarize whether the local native runtime appears ready before starting the native pipeline.
- Added an Electron native pipeline no-frame startup warning so startup can report a clearer local readiness problem when the pipeline starts but MotionFrame data does not arrive within the expected window.
- Improved Web Preview native-source status guidance so native-source users get clearer status copy while waiting for, receiving, or missing localhost MotionFrame data.
- Added renderer-side Web Preview calibration preset polish for the native face-following path while keeping the behavior in the renderer layer rather than changing the MotionFrame protocol.

## Validation performed

The v0.4.0 implementation slices added or exercised focused automated coverage for the local runtime confidence paths, including:

- `pnpm format:check` for repository formatting.
- Web Preview native status checker scripts for native-frame status copy and status badge behavior.
- Electron checker scripts for native runtime capability/readiness reporting and no-frame startup warning behavior.
- `pnpm test` where implementation PRs changed source or package behavior.
- Local native dummy pipeline smoke coverage through `pnpm smoke:native-dummy-pipeline:local` / `tools/check-native-dummy-pipeline-ws-smoke.mjs`, where the built native tracker is available.

This release-readiness closeout is docs-only. It does not add a new local/manual validation claim. Webcam, OBS, Electron GUI, packaged Electron, hardware-specific, and OpenCV camera checks remain owner-performed local/manual checks unless a separate report records that they were actually performed.

## Non-goals and preserved boundaries

- No `MotionFrame` schema change.
- No Motion Protocol change.
- No new tracking backend beyond the current local prototype/runtime confidence work.
- No production backend, model, runtime, task, cascade, binary, generated artifact, packaged runtime, or runtime-download selection.
- No real eye tracking, mouth tracking, expression tracking, landmark tracking, or blendshape tracking.
- No cloud upload, telemetry, analytics, remote inference, external frame processing, runtime downloads, hidden network behavior, or new external network behavior.
- No raw frame IPC, pixel IPC, tensor IPC, helper-owned camera capture, or external camera-frame processing claim.
- No webcam, OBS, Electron GUI, packaged Electron, hardware, or local/manual validation claim from this closeout note.

## Remaining local/manual checks

These checks remain environment-dependent and should only be marked complete when the project owner or another local operator performs them on suitable hardware/software and records the result safely:

- Electron GUI visual check for native runtime readiness and no-frame startup warning states.
- Webcam/OpenCV path validation when intentionally tested with local camera hardware, OS camera permission, and an OpenCV-enabled native build.
- OBS/browser visual check for `http://localhost:5173/?mode=obs&source=native` while receiving local MotionFrame data.
- Packaged Electron validation for the current build and native runtime staging state.
- Hardware-specific validation across target machines, cameras, GPU/driver combinations, and OS camera-permission configurations.

## Next direction

Continue toward evidence-based local backend evaluation, calibration polish, and avatar integration planning while preserving the local-first privacy boundary, current MotionFrame/Motion Protocol compatibility, and clear Web Preview/Electron runtime responsibilities.
