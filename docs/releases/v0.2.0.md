# v0.2.0 Release Notes Draft

## Release intent

v0.2.0 is the **Local OpenCV Face-Following MVP** release for LVK.

This release prepares the repository for the first local OpenCV-backed face-following workflow while preserving the local-first privacy boundary: camera frames stay local, MotionFrame data is transported over localhost for preview consumption, and no telemetry, analytics, cloud upload, external frame processing, runtime downloads, or new network behavior is introduced by this release prep.

## Included

- Simple local face-following through the Native Core OpenCV camera and face detector path.
- Native Core OpenCV face detection diagnostics and stabilization, including fresh, held, and none result-source diagnostics from local smoke validation.
- `MotionFrame` `face.position.x`, `face.position.y`, and `face.position.z` values driven by OpenCV face bounds.
- Electron development native runtime root-resolution fixes so the dev launch path does not require copying the native tracker into the desktop app tree.
- Web Preview consumption of native MotionFrame data.
- Web Preview debug, status, and fallback behavior improvements for native-source workflows.
- Web Preview renderer-side smoothing for native face-following movement.
- Local-first operation: raw camera frames remain local to Native Core memory during OpenCV camera workflows.

## Known limitations and non-goals

- OpenCV support is Haar-style face detection only.
- v0.2.0 does not include real eye tracking, real mouth tracking, expression tracking, or landmark tracking.
- v0.2.0 does not include a landmark backend.
- v0.2.0 does not include GLB, VRM, custom avatar loading, bone mapping, or morph target mapping.
- `MotionFrame` schema version remains `1`; this release prep does not change the MotionFrame contract.
- Packaged Electron validation is only claimed where an owner-performed local smoke report explicitly records it. The most recent 2026-07-02 local smoke report did not validate packaged Electron.
- Local OpenCV runtime and DLL availability remain local setup concerns where applicable.
- Native face-following movement can still appear angular or blocky; smoothing improves renderer behavior but does not turn Haar face detection into landmark or expression tracking.
