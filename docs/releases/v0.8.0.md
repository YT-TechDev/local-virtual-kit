# v0.8.0 Release Readiness Notes

## Summary

v0.8.0 is the **first user-facing Web Preview renderer calibration workflow**.

It builds on the existing renderer-side face-following calibration foundation by making calibration persistent, actionable, understandable, source-aware, safer across invalid local state, and excluded from OBS control output. It is not a tracking backend improvement and does not introduce a new native tracking release.

The implementation landed through these merged PRs:

- #493, merge commit `1c1669da34958887eaa2eff9c6b4a7575b14401d` — persist Web Preview renderer calibration preset.
- #494, merge commit `648758475cd6596268ddfa0a7f764fee4a8315e3` — add renderer neutral-pose capture controls.
- #495, merge commit `8eef51dea145e4e211a2e69a8a52861ad78e80fd` — improve the Web Preview renderer calibration panel.

## Completed slices

- #489 / PR #493 added browser-local persistence for the selected renderer calibration preset, a versioned renderer calibration storage boundary, runtime validation for persisted state, and safe fallback for missing data, malformed JSON, unsupported versions, unknown preset IDs, and unavailable or throwing browser storage. Storage is accessed only at runtime, not at module import, and no server, cloud, telemetry, or remote synchronization was added. The initial persisted shape was:

  ```ts
  {
    version: 1;
    presetId: "balanced" | "steady" | "responsive";
  }
  ```

- #490 / PR #494 evolved persistence to the current v2 shape:

  ```ts
  {
    version: 2;
    presetId: FaceFollowingPresetId;
    neutralCenter: {
      x: number;
      y: number;
      z: number;
    } | null;
  }
  ```

  Valid v1 preset-only data remains compatible and restores the preset with no custom neutral center. Valid v2 data restores the preset and optional custom neutral center. Invalid custom center data falls back safely to no custom center, and finite normalized center values are bounded by the existing renderer calibration domain. Only minimal renderer calibration configuration is persisted.

- #490 / PR #494 added native neutral-pose capture and reset controls. Capture uses the latest valid native `MotionFrame.face.position` only when `source === "native"`, native status is `connected`, a current native frame exists, and `tracking.status === "tracking"`. Dummy, connecting, waiting, reconnecting, stale fallback, lost, and no-frame states cannot be captured. Capture changes only the renderer neutral center; active preset sensitivity, deadzone, and smoothing remain intact. Changing presets preserves a captured custom neutral center, reset returns to the selected preset default center, and calibration changes reset incompatible renderer smoothing/fallback state. The native tracker is not recalibrated.

- #491 / PR #495 improved the calibration panel UX by separating source/runtime diagnostics from renderer calibration controls, displaying the active preset and neutral-center state (`Custom` or `Preset default`), adding source-aware capture availability guidance and disabled-state explanations, disabling reset when no custom center exists, and adding localized polite feedback for preset changes, capture, and reset. Feedback events are revisioned so repeated identical actions restart feedback timing and can produce a fresh live-region update. The panel also gained keyboard focus and disabled styling, narrow-screen wrapping, preservation of endpoint copy, frame diagnostics, fallback guidance, and privacy messaging, plus removal of one broad atomic live region around all controls. This is not a formal screen-reader certification or WCAG conformance claim.

## Architecture and privacy boundaries

v0.8.0 does not change the `MotionFrame` schema, Motion Protocol, Native Core, native tracking algorithms, Electron calibration synchronization, localhost MotionFrame transport, camera access, or tracking backend selection.

Native Core still owns camera access and tracking. Web Preview owns renderer calibration state, mapping, controls, and feedback. `MotionFrame` remains the stable contract between Native Core and renderer. Browser-local renderer calibration is not described as Electron-owned settings.

The standard source-status panel and renderer calibration controls remain excluded from OBS mode. Persisted renderer calibration can still affect avatar rendering in OBS mode, but no calibration control panel is rendered into the OBS-friendly output. The optional `debug=motion` overlay is a separate explicitly requested diagnostic path and may still render when enabled. No OBS visual validation was performed for this closeout.

v0.8.0 persists only the preset ID and optional normalized neutral center. It does not persist camera frames, images or pixels, `MotionFrame` objects, `MotionFrame` history, frame timestamps, frame counts, tracking confidence history, raw tracking history, source diagnostics, or action feedback.

v0.8.0 adds no telemetry, analytics, cloud upload, remote inference, remote synchronization, external frame processing, runtime downloads, hidden network behavior, or new network behavior. Camera frames remain local.

## Known limitations and remaining local/manual checks

Known limitations, none of which are regressions:

- Renderer calibration is browser-local and is not synchronized through Electron.
- No calibration import/export or cross-device synchronization was added.
- No free-form sensitivity, deadzone, or smoothing sliders were added.
- Neutral pose uses the current native `face.position`, not landmarks or a richer facial model.
- Current tracking quality remains limited by the existing native tracking path.
- No real eye, mouth, expression, landmark, or blendshape tracking was added.
- No VRM, GLB, or custom avatar loader was added.
- Manual browser/native/OBS/accessibility validation remains incomplete.

Preserved non-goals:

- No MediaPipe integration or enablement.
- No production tracking backend selection.
- No model/task assets.
- No runtime downloads.
- No Native Core tracking algorithm changes.
- No MotionFrame or Motion Protocol changes.
- No Electron calibration synchronization.
- No free-form sensitivity/deadzone/smoothing sliders.
- No VRM, GLB, or custom avatar loader.
- No telemetry, analytics, cloud upload, remote inference, or external processing.
