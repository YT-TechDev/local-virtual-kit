# v0.6.0 Release Readiness Notes

## Summary

v0.6.0 is a **Local backend candidate validation spike** after v0.5.0's Native Core backend evaluation foundation.

This release-readiness note closes the v0.6.0 evidence pass by recording OpenCV cascade-backed baseline evidence, the first local backend candidate route decision, the no-dependency fail-closed MediaPipe Face Landmarker candidate scaffold, and MotionFrame compatibility evidence for that scaffold.

v0.6.0 does **not** select, approve, or ship a production tracking backend. LVK remains local-first: camera frames stay local, `MotionFrame` remains stable, and backend/runtime details stay behind Native Core boundaries.

## Completed slices

- #469 recorded v0.6.0 OpenCV cascade-backed baseline evidence. An OpenCV-enabled Native Core build was confirmed locally, a trusted local Haar cascade path was used, and cascade-backed smoke plus backend parity checkers passed with `--camera-source dummy` synthetic frames. No live webcam/camera hardware was validated, and no cascade XML, raw frames, generated artifacts, binaries, or build outputs were committed. OpenCV Haar remains smoke/baseline only and is not a production backend.
- #470 added `docs/TRACKING_BACKEND_V0_6_CANDIDATE_ROUTE_DECISION.md`. It compared OpenCV Haar continuation, MediaPipe Face Landmarker, ONNX Runtime plus a local model, and other local-only routes. It recommended a **MediaPipe Face Landmarker local candidate feasibility spike behind the Native Core `TrackingBackend` boundary** as the first candidate spike route, without selecting a production backend or approving dependencies, model/task assets, runtime packages, or runtime downloads. ONNX Runtime remains deferred until a concrete model candidate, license, redistribution plan, output mapping, and provider/runtime setup are identified.
- #471 added a no-dependency, fail-closed MediaPipe Face Landmarker candidate scaffold. It added `--tracking-backend face-pipeline|mediapipe-face-landmarker`, kept `face-pipeline` as the default, added compile-time `LVK_HAS_MEDIAPIPE_FACE_LANDMARKER` defaulting to `0`, and reported runtime capabilities with `mediapipeFaceLandmarkerSupport=false` and `supportedTrackingBackends=face-pipeline`. Selecting unsupported `mediapipe-face-landmarker` fails closed before camera open and before MotionFrame stdout emission. It also added `tools/check-native-mediapipe-candidate-boundary.mjs` and `pnpm test:native-mediapipe-candidate-boundary` without adding MediaPipe, ONNX Runtime, model/task/cascade assets, runtime packages, runtime downloads, inference, or production backend selection.
- #472 strengthened `tools/check-native-mediapipe-candidate-boundary.mjs` and verified that the default path and explicit `--tracking-backend face-pipeline` emit the same MotionFrame stdout JSON schema. It also verified that unsupported `mediapipe-face-landmarker` emits no MotionFrame stdout and fails closed before camera open, while runtime capabilities still report `mediapipeFaceLandmarkerSupport=false` and `supportedTrackingBackends=face-pipeline`. This did not change MotionFrame, Motion Protocol, or claim real MediaPipe inference, landmarks, blendshapes, transformation matrices, webcam, OBS, Electron GUI, packaged Electron, or hardware validation.

The completed v0.6.0 slices reported the following validation across their PRs:

- `pnpm test`

- `pnpm test:native-backend-parity-motionframe`

#469 collected OpenCV cascade-backed evidence with a trusted local cascade path and an OpenCV-enabled build, but it used dummy/synthetic frames and did not validate a live webcam/camera path.

#471 and #472 ran in an environment where OpenCV support may have been unavailable. Where runtime capabilities reported `opencvFaceDetectorSupport=false`, OpenCV parity output was skipped rather than treated as live OpenCV validation.

## Non-goals and preserved boundaries

v0.6.0 preserves the following boundaries:

- No production backend selection, approval, or shipping claim.
- No MediaPipe dependency.
- No ONNX Runtime dependency.
- No model/task/cascade asset.
- No runtime package.
- No runtime download.
- No generated artifact or binary.
- No inference.
- No MediaPipe landmark, blendshape, or transformation output claim.
- No MotionFrame schema change.
- No Motion Protocol change.
- No cloud upload, telemetry, analytics, remote inference, external frame processing, hidden network behavior, or new network behavior.
- No raw frame IPC, pixel IPC, or tensor IPC.
- No Electron or Web Preview dependency on backend runtime packages.
- No webcam, OBS, Electron GUI, packaged Electron, or hardware validation claim unless separately recorded.

## Remaining local/manual checks

The following checks remain future local/manual work and are not claimed by v0.6.0:

- Live webcam/camera validation for candidate paths.
- Real MediaPipe integration feasibility with dependency, build, license, task, and model handling in a future scoped PR.
- MediaPipe task/model license, notice, redistribution, and packaging review.
- Runtime packaging/staging for any future approved dependency.
- OBS Browser Source visual validation.
- Electron GUI/runtime readiness validation if intentionally revalidated.
- Packaged Electron validation.
- Hardware/platform checks across target machines.
