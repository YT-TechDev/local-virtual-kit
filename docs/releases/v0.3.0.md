# v0.3.0 Release Notes Draft

## Release intent

v0.3.0 is a **local tracking quality and release-readiness** release for LVK after the v0.2.0 Local OpenCV Face-Following MVP.

This release readiness pass captures the completed v0.3.0 roadmap work without expanding runtime scope. It keeps LVK local-first, preserves the existing `MotionFrame` contract, and records H2/helper-runtime work as guarded preparation rather than production backend selection or readiness validation.

## Included

- Post-v0.2 README and documentation navigation consolidation so contributors have a smaller current-entrypoint set for release, roadmap, runtime checklist, architecture, protocol, mapping, and development-policy references.
- Local face-following calibration and sensitivity baseline work for the Web Preview native face-following path.
- Packaged Electron runtime validation follow-up preparation, without claiming packaged Electron validation from this release-readiness PR.
- H2 helper-runtime supervisor planning and fail-closed guard coverage.
- Helper launch-failure and ready-timeout guard coverage so helper startup failures remain bounded and explicit.
- No-dependency synthetic helper adapter smoke coverage behind the Native Core boundary.
- Preservation of the existing dummy/noop MotionFrame path and the OpenCV Haar baseline path.

## Boundaries and non-goals

- No `MotionFrame` schema change.
- No Motion Protocol change.
- No backend dependency, model file, runtime download, or production H2 default wiring.
- No backend, model, runtime, task, cascade, binary, generated artifact, or packaged runtime selection.
- No fallback MotionFrame behavior, retry/backoff behavior, real camera access, helper-owned camera capture, raw frame IPC, pixel IPC, tensor IPC, Electron behavior, or Web Preview behavior change from these release notes.
- No telemetry, analytics, cloud upload, remote inference, external frame processing, hidden network behavior, runtime download behavior, or new network behavior.
- No local/manual webcam, OBS, Electron GUI, packaged Electron, or readiness validation claim unless separately performed and safely recorded by the project owner.

## Validation notes

This release-readiness PR should run automated repository checks only. It should not claim new webcam, OBS, Electron GUI, packaged Electron, local hardware, or production-readiness validation unless that validation is actually performed and explicitly recorded.

The v0.3.0 notes intentionally describe H2/helper-runtime work as planning, guard coverage, and synthetic smoke coverage behind the Native Core boundary. They do not make H2 the production default and do not approve raw frame, pixel, or tensor IPC.
