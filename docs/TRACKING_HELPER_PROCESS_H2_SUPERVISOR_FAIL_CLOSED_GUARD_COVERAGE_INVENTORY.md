## Source Boundary Read

Current coverage is bounded by the explicit smoke path selected with `lvk-tracker-core --helper-runtime-smoke <helper> --helper-runtime-smoke-case <case>`. The default Native Core runtime remains outside H2 helper supervision unless `--helper-runtime-smoke` is provided.

Primary source/checker locations:

- `native/tracker-core/src/helper_runtime_smoke.h` declares the explicit smoke-only cases and documents each guard boundary.
- `native/tracker-core/src/helper_runtime_smoke.cpp` maps smoke cases to synthetic helper arguments, applies bounded supervisor timeouts, observes lifecycle boundaries from private captured helper stdout, parses only known helper stdout records, and emits safe parent diagnostics.
- `native/tracker-core/src/main.cpp` exposes the explicit `--helper-runtime-smoke-case` selector only when `--helper-runtime-smoke PATH` is supplied.
- `tools/check-helper-runtime-integration.mjs` is the source-grounded checker that asserts exit status, public stdout shape, public stderr prefixing, and absence of helper stdout/stderr leakage.

## Notes on Existing Fallback Cases

The older explicit `launch-failure`, `nonzero-exit`, and `timeout` smoke cases still assert their pre-existing behavior: they emit exactly one existing fallback MotionFrame and exit 0 while keeping public stdout MotionFrame JSON only and helper streams private. The lifecycle-handshake failure vectors are the stricter terminal/fail-closed evidence for #400/#431/#432: they exit non-zero and leave public stdout empty.

This inventory does not approve fallback MotionFrame behavior. It only records that the existing fallback cases remain covered as existing smoke behavior while the H2 supervisor terminal/fail-closed lifecycle and parse guards are covered by empty-stdout fail-closed vectors.

## Decision

Recommendation: **All current synthetic H2 supervisor terminal/fail-closed conditions in this inventory are covered; move to the next #400 implementation-entry decision.**

No additional micro-guard is recommended from this inventory. The only partial note is intentionally scoped: `bounded-oversized-stdout-line` covers the current deterministic bounded oversized fixture and public/private stream boundary, but it is not a production line-size, streaming parser, buffer-management, or memory-pressure policy. That limitation is already explicit in the current checker/source comments and does not require a new #400 micro-guard before the next implementation-entry decision.

#400 remains open.
